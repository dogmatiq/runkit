## Context

Dogma v0.26.0 changes each UUID that Dogma or the engine supplies at run time
from a `string` to Go 1.27's `uuid.UUID` ([ADR 36]). It also adds `MessageID()`
to every scope in which a handler handles a message ([ADR 37]). An application
that uses Dogma v0.26.0 can't build with runkit until runkit implements the new
methods and signatures. #122 is in the v0.3.0 milestone.

runkit holds almost every ID as a `*uuidpb.UUID`, in about 70 files, and keeps
sets and maps of them in `enginekit/uuidcollection`. Decided in planning:

- **runkit holds every UUID as a `uuid.UUID`.** A `*uuidpb.UUID` appears only
  as a field of a protobuf message: an envelope, an `identitypb.Identity`, or a
  gRPC request or response. runkit calls `AsStd()` when it takes an ID out of a
  protobuf message to use it, and `FromStd()` when it builds one.
- **This happens before v0.3.0, as part of #122.**
- **runkit gets a set type of its own now, as #107 describes**, holding
  `uuid.UUID`. Each `uuidcollection.Map[T]` becomes a plain `map[uuid.UUID]T`.
- **The set type has a read-only view**, as #107 asks, and shared sets are
  returned as that view. This replaces the convention of only documenting that
  callers must not modify them.
- **The rule is written down** in `docs/maintainers/uuids.md`.

No exported API mentions `*uuidpb.UUID` or `uuidcollection`, so the conversion
needs no changelog entry.

[ADR 36]: https://github.com/dogmatiq/dogma/blob/main/docs/adr/0036-native-uuid-type.md
[ADR 37]: https://github.com/dogmatiq/dogma/blob/main/docs/adr/0037-expose-message-ids.md

## Words

- **message ID**: Dogma's glossary term from [ADR 37]. It is the UUID that
  identifies a message, and it is the same every time the engine delivers the
  message, to any handler. runkit already stores it in each envelope. Each scope
  holds it in the field `messageID`.
- **The set type, its read-only view and their package** are new names. Their
  candidates are presented at the start of the set task, as the
  words-before-code trial does.
- Docs and comments say "`uuid.UUID`" and "`*uuidpb.UUID`", never "native UUID"
  or "proto UUID".

## Settled design

- **Where the protobuf boundary is.** These are the places where runkit takes
  IDs out of protobuf messages or puts them in:
  - envelopes: the message ID, type ID, causation ID and correlation ID, and
    the source identities;
  - `identitypb.Identity.Key`, from `config.*.Identity()`;
  - the event stream gRPC messages: `ReadEventsRequest.event_stream_id`,
    `EventStreamSegment.event_stream_id`, the type IDs in `MessageFilter`, and
    `EventStreamPosition.stream_id`.

  An ID received from a gRPC peer is checked with `Validate()` before
  `AsStd()`, as today. Sinks keep `Identity *identitypb.Identity`, because the
  packer needs it, and call `GetKey().AsStd()` where they need the key as an
  ID. That call doesn't allocate.
- **NULL in the database.** `xsql.UUID` maps SQL NULL to the zero `uuid.UUID`
  in both directions. Today a NULL is read as the zero UUID and a nil pointer
  is written as NULL. The zero UUID is never a real ID, because runkit's IDs
  are version 4 or version 5 UUIDs. So `aggregate/instance.go` writes a zero
  stream ID where it now writes a nil pointer, and the checks against
  `.Equal(nil)` become `== uuid.UUID{}`.
- **Rendezvous keys are derived exactly as today.** The version 5 UUID uses the
  handler key as its namespace and the stream ID's lowercase text as its name,
  and `uuid.UUID.String()` produces the same text as `AsString()`. The standard
  library has no version 5 function, so runkit still calls `uuidpb.Derive()`
  and converts its result. The existing test in
  `internal/projection/eventsink_test.go` that compares `RendezvousKey()` with
  `uuidpb.Derive()` stays.
- **Signal topics don't change.** `"heartbeat."`, `"messages_enqueued."` and
  `"events_appended."` are followed by the ID's lowercase text, as now.
- **While the conversion is in progress**, `xsql.UUID`, `xsql.UUIDSeq` and
  `xslog.UUID` are generic over `uuid.UUID` and `*uuidpb.UUID`, so their call
  sites don't change until their package converts. The last conversion task
  removes the `*uuidpb.UUID` forms. Where a converted package meets one that
  isn't converted yet, the unconverted side calls `AsStd()` or `FromStd()`, and
  that package's own task removes the call. Test helpers in
  `internal/x/xtesting` move in the task of the concept they serve.
- **Dead code that would otherwise need converting is deleted instead.**
  `xsql.UUIDs` has no callers.

## Tasks

### [x] Finish the Dogma v0.26.0 upgrade

Rebase `dogma-v0.26` onto main, resolving the `CHANGELOG.md` conflict, and
force-push it. Then fix the problems in #133:

- **Changelog.** Its entry sits above the **[BC]** entries, with a blank line
  between them, and isn't tagged. Replace it with one entry under `### Changed`,
  following the maintaining-changelogs skill. It is tagged **[BC]**, and says
  that runkit now needs Dogma v0.26.0 and that handlers can read each message's
  ID from `MessageID()`. An earlier release already says that Go 1.27 is
  required, so this entry doesn't repeat it.
- **Field order.** In `process.messageScope`, `messageID` goes after the
  exported fields, because only the scope's own method reads it. In the other
  scopes it stays first. Each struct literal sets it in the same position.
- **Method order.** Put `MessageID()` right after `Now()` and `Log()`, where
  Dogma's interfaces declare it, not at the end of each file.
- **Tests.** The PR puts message ID assertions inside unrelated tests. In the
  integration sink test, it builds the stub with `HandleCommandFunc: handle`
  and then replaces the function. Replace those assertions with one focused
  subtest per sink: "it passes the ID of the delivered message to the handler".
  Add the same subtest for the aggregate command sink and the projection event
  sink. The PR doesn't test those two, which is why `codecov/patch` fails. A
  redelivery reads the same stored envelope, so comparing with the envelope's
  ID also covers "the same every time".

### [x] Give runkit a UUID set type (#107)

Names, chosen in review: the package `uuidset`, the set `uuidset.Set` and the
read-only view `uuidset.SetR`. `SetR` is a struct that wraps a `*Set`, so its
zero value is an empty set and no nil view can exist. The package has exactly
the operations that runkit's non-test code calls on `uuidcollection.Set` today:
`Add`, `Delete`, `Has`, `Len`, `IsEmpty`, `All`, `Clone`, `IsEqual`, `Diff` and
a sorted `String`, which the event stream catalog's error message uses. Reads of
a nil `*Set` behave as reads of an empty set. The read methods accept a `SetR`,
so comparing a shared set with a local one needs no conversion. The package has
its own tests, following the testing-in-go skill. Nothing uses it until the next
task.

### [ ] Convert `internal/cluster` to `uuid.UUID`

This covers node IDs, rendezvous keys and the live-node set. `Node.LiveNodes()`
returns the read-only view. `Engine.nodeID` comes from `uuid.New()`, and the
heartbeat topic is parsed with `uuid.Parse()`. This task makes `xsql` and
`xslog` generic and deletes `xsql.UUIDs`. Callers in `messagequeue` and
`eventstream` convert at the boundary for now.

### [ ] Convert `internal/messagequeue` to `uuid.UUID`

This covers queue IDs, message IDs and message type IDs in the router, catalog,
consumer, delivery and `Delivery`. `Catalog.QueueIDs()` returns the read-only
view. `contendedMessages` and `detachQueueSignal` become maps, and
`attemptsInProgress` becomes a set. `CommandHandlers` becomes a map keyed by
`uuid.UUID`. The command queue helpers in `xtesting` move here too.

### [ ] Convert the event stream packages to `uuid.UUID`

This covers `internal/eventstream`, `eventstream/internal/cache`,
`eventstream/source` and `remoteengine`: stream IDs, sets of message type IDs,
the remote engine ID, and the `Sink` interface (`RendezvousKey`,
`CheckpointOffset`, `EventTypeIDs`). The gRPC client and server convert at the
protobuf boundary. The catalog's sets become read-only views. The event stream
helpers in `xtesting` move here too.

### [ ] Convert the handler packages to `uuid.UUID`

This covers `aggregate`, `integration`, `process`, `projection` and
`application`: handler and application keys, stream IDs, deadline queue IDs,
and the sinks' `RendezvousKey()`. The NULL handling described above lands here.
The `AsStd()` calls that the upgrade task added for the projection's stream ID
go away.

### [ ] Convert the engine and finish the conversion

This covers the root package (`engine.go`, `routes.go`, `execute.go`,
`handler.go`) and whatever is left in `xtesting` and `xmessage`. It removes the
`*uuidpb.UUID` forms of the `xsql` and `xslog` helpers. Afterwards nothing
imports `uuidcollection`, and every remaining use of `uuidpb` is a protobuf
builder or getter, `Validate()`, `AsStd()`, `FromStd()` or `Derive()`. Add
`docs/maintainers/uuids.md` beside `logging.md` and `schema.md`. It states the
rule and lists the protobuf boundaries, so that new code doesn't use
`*uuidpb.UUID` just because envelopes do.

The event observer fix (see below) must land before this task. Otherwise
`execute.go`'s zero map, which is passed by value, becomes a nil Go map, and
the first write to it panics.

## Outside this plan

- **The event observer bug.** File an issue in the v0.3.0 milestone and fix it
  in its own PR, with a `### Fixed` changelog entry. `waitForEvents` passes a
  zero `uuidcollection.Map` to `pollForEvents` by value, so the offsets that
  are recorded are lost. Every poll then re-reads events from offset 0, and the
  observers given to `ExecuteCommand()` see the same events on every poll and
  never see any event after the first 100. v0.2.0 has the same bug.
